### 实现时对设计做的两处调整（已在代码中注明理由）

1. **用户规则优先级提到浏览器判定之前**（`RuleEngine.Classify` 第 4 步）。
   否则"一键纠错"在浏览器页面上不生效 —— 站点表会先把结果定下来。
2. **自动结束会话用"连续离开时长"而不是"会话累计空闲 + 挂起"**（`TimerEngine.CheckAutoEnd`）。
   需求场景是"人走了忘记停止"；若用会话累计，正常工作一天里断续摸鱼累加起来会被误判成离开，
   把还在上班的会话结束掉。配置项 `idle.autoEndSessionAfterMinutes` 语义即"连续离开多久自动结束"。

## 1. 项目目标

Windows 桌面常驻工具，记录"**注意力真正投入工作的时长**"：

- 用户**手动**开始 / 停止计时，不自动开始。
- 计时期间持续监测**前台激活窗口**，判定是否在工作。
- 前台是娱乐类（游戏 / 视频 / 聊天）且**连续累计超阈值**时自动挂起，**该段整体作废**。
- 切回工作软件或系统组件后自动恢复计时。
- **只关注前台窗口**，后台挂任何软件都不影响计时。
- 形态：**托盘常驻 + 主窗口 + 可贴边隐藏的悬浮窗**（加速球风格）。
- 提供统计、分项目计时、右键菜单、设置与配置文件。

### 口径声明（先对齐认知）

统计的是 **"前台焦点时间"**，不是"CPU 在忙的时间"：

- 后台跑编译 / 下载 / 训练，前台在浏览网页 → 计的是浏览器那段（按判定结果）。
- 双屏时 A 屏放视频、B 屏写代码，焦点在 B → 算工作。**判定跟着焦点走。**
- 读代码 / 看资料时会不时点选、滚动，不会长时间静止，因此 20 分钟空闲规则不会误伤（见 §14-Q1 的保留开关）。

### 非目标

- ❌ 跨设备 / 云端同步　❌ 团队管理、上报审批　❌ 键鼠记录、截屏等内容审查　❌ 移动端 / Web 端
- ⏸ 数据备份 / 麦克风占用检测（列入后续版本考量）

## 4. 核心：判定引擎

### 4.1 采样（2 秒）

| 字段 | 来源 |
|---|---|
| `Hwnd` | `GetForegroundWindow()`（可能 `NULL`） |
| `Pid` | `GetWindowThreadProcessId()` |
| `ProcessName` | `QueryFullProcessImageName`，失败降级 `Process.ProcessName` |
| `ProcessPath` | 同上，提权进程可能取不到 → 留空 |
| `WindowTitle` | `GetWindowTextW`（为空则降级 `SendMessageTimeout(WM_GETTEXT)`） |
| `WindowClass` | `GetClassNameW` |
| `IsFullscreen` | 窗口矩形 == 所属显示器矩形（`MonitorFromWindow` + `GetMonitorInfo`） |
| `IdleSeconds` | `GetLastInputInfo()` |

- **采样并入整合**：2 秒一次采样，但**不逐条落库**，而是交给 `SegmentBuilder` 合并成"窗口段"（§4.8）。
- **UWP 特例**：前台进程为 `ApplicationFrameHost` 时，用 `EnumChildWindows` 找 `Windows.UI.Core.CoreWindow` 子窗口取真实 PID 与标题。
- **触摸屏输入**：`GetLastInputInfo` 统计系统级最后输入时间，鼠标 / 键盘 / 触摸通常都会刷新。本机有触摸屏，**降级方案（RawInput 监听）暂缓**，实测有问题再补（§14 备注）。

### 4.2 防抖（5 秒）

某窗口**连续占据前台 ≥ 5 秒**才认定为"窗口切换"。实现用**时间累加**判定（`now - candidateSince >= 5s`），不依赖采样次数，这样调整采样间隔不改变防抖语义。

作用：微信新消息弹窗、系统通知、输入法候选、Alt+Tab 途经的任务视图、点任务栏图标的一瞬间，都不打断计时。

### 4.3 窗口分类

| 分类 | 含义 | 默认阈值 |
|---|---|---|
| `Work` | 工作软件、文件资源管理器、会议/协作办公类 | ✅ 计时 |
| `Game` | 游戏 | 5 分钟 |
| `Video` | 视频播放器 / 视频站点 | 10 分钟 |
| `Chat` | 纯社交聊天工具 | 10 分钟 |
| `Neutral` | 无法判定 | 默认计入工作 |
| `Inherit` | 无前台窗口 / 系统外壳 / 本程序自身窗口 | **保持上一有效分类，不改变计时状态** |

**`Inherit` 涵盖**：`GetForegroundWindow()` 返回 `NULL`、桌面（`Progman` / `WorkerW`）、任务栏本体（`Shell_TrayWnd`）、开始菜单（`StartMenuExperienceHost` / `XamlExplorerHostIslandWindow`）、通知中心（`ShellExperienceHost`）、任务视图（`MultitaskingViewFrame`）、锁屏（`LogonUI.exe`）、本程序自身窗口。

> 注意：文件资源管理器真实窗口（`explorer.exe` 的 `CabinetWClass`）**仍是 `Work`**，只有任务栏本体和桌面算 `Inherit`。

### 4.4 规则匹配

顺序 **first-match-wins**：用户自定义规则 → 内置规则库 → 兜底（`Neutral` → 计入工作）。

单条规则结构（新增 `suppressIdle` 标记）：

```json
{
  "id": "u-1", "enabled": true, "order": 10, "category": "work",
  "processPattern": "devenv*", "titlePattern": null, "titleIsRegex": false,
  "classPattern": null, "matchMode": "process",
  "thresholdMinutes": null, "suppressIdle": false,
  "note": "Visual Studio"
}
```

**内置规则库**

- **`Work`**：`devenv`、`Code`、`rider64`、`idea64`、`pycharm64`、`webstorm64`、`sublime_text`、`WindowsTerminal`、`powershell`、`pwsh`、`cmd`、`conhost`、`mstsc`、`explorer`(`CabinetWClass`)、`WINWORD`、`EXCEL`、`POWERPNT`、`wps`、`et`、`wpp`、`notepad`、`Notepad++`、`Everything`、`SnippingTool`、`GitExtensions`
- **`Work`（会议 / 协作，`suppressIdle: true`）**：`wemeetapp` / `TencentMeeting`、`Zoom`、`Teams` / `ms-teams`、`Feishu` / `Lark`、`DingTalk`、`WXWork`、`Slack`
- **`Work`（桌面客户端形态的 AI / 文档工具）**：`Cursor`、`chatgpt`、`Claude`、`Ollama`、`Notion`、`Obsidian`、腾讯文档、`kdocs`、百度文库
- **`Chat`**：`WeChat` / `Weixin`、`QQ`、`TIM`、`Telegram`、`Discord`、`WhatsApp`、`Line`、`Messenger`
- **`Video`**：`PotPlayerMini64`、`vlc`、`mpv`、`mpc-hc64`、`bilibili`、`QQLive`、`iqiyi`、`YoukuClient`、`douyin`、`TikTok`
- **`Game`**：`steam`、`steamwebhelper`、`wegame`、`EpicGamesLauncher`、`Battle.net`、`GalaxyClient`、`LeagueClient`、`dota2`、`cs2`、`GenshinImpact`、`YuanShen`、`StarRail`
  ＋ 后备信号"**独占全屏 + 未命中任何其他规则 → 疑似游戏**"（默认关，设置可开）

**新增开关：把 IM 强制归工作**（§14-Q2 的答复）

设置 → 应用分类 → 「工作场景聊天工具」：微信 / QQ / TIM 三个独立开关，勾上则该软件归 `Work` 全时计入。默认全关（归 `Chat`）。适合"用 QQ 对接工作"的日子临时打开。

### 4.5 阈值状态机

#### 4.5.1 状态定义

| 状态 | 含义 | 是否计时 |
|---|---|---|
| `Stopped` | 用户未开始 | ❌ |
| `Working` | 正常计时 | ✅ |
| `PendingEntertainment` | 娱乐窗口已进入，尚未判定（见 4.5.4） | 视模式而定 |
| `SuspendedAuto` | 娱乐连续超阈值 → 自动挂起 | ❌ |
| `PausedByUser` | 用户手动暂停 / 退出程序时保存 | ❌ |
| `IdleAway` | 无输入超 20 分钟 | ❌（可配为照常计时） |

#### 4.5.2 娱乐连续运行（EntertainmentRun）

不再按类别独立计时，改为维护**一个跨类别连续运行**：

```
EntertainmentRun {
  startAt          // 本次娱乐连续运行的起点
  currentCategory  // 当前所在娱乐类别
  visitedCategories[] // 运行期内出现过的类别，用于阈值策略计算
  segments[]       // 运行期内的窗口段
}

采样 → category:

  Work / Neutral     → run 结束，进入"结算"（4.5.3）
  Inherit            → 完全不动：run 继续、计时继续、状态不变
  Game/Video/Chat    → run 未开启则 startAt = now
                       currentCategory = category；visitedCategories += category
                       阈值 = 按 §4.5.6 的策略算出
                       if (now - run.startAt) >= 阈值 → SuspendedAuto，写 SUSPEND 事件
```

**要点**：娱乐类别之间切换**不清零**（游戏玩 4 分钟 → 切视频，run 继续累加）；只有切回 `Work` / `Neutral` 才结束 run；`Inherit` 期间 run 与状态**都保持不变**。

#### 4.5.3 结算（追溯作废）

- run **超阈值被判定** → 整段 `[startAt, now]` **作废**，不计入有效工时，累加进 `session.suspended_seconds`。
- run **在阈值内结束** → 整段**计入**有效工时。

#### 4.5.4 计时器数字是否回退（用户可选，默认不回退）

| 模式 | 开关 | 行为 |
|---|---|---|
| **待判定（默认）** | `timing.countEntertainmentLive = false` | 进入娱乐窗口后，主计时器**暂停跳动**并显示灰色/橙色"待判定 03:12"。run 结束时一次性结算：未超阈值 → 补入；超阈值 → 丢弃。**数字只增不减** |
| **实时计入** | `timing.countEntertainmentLive = true` | 进入娱乐窗口后照常计时，超阈值时把这部分**扣回**。计时器能真实反映"此刻已计时多久"，但数字会回跳 |

> ⚠️ **两种模式的最终工时数据完全一致**，差异只在显示行为。这是纯粹的观感偏好，用户随时可切。

#### 4.5.5 空闲（AFK）与会议抑制

- `IdleSeconds ≥ 20 分钟`（可配）→ `IdleAway`；有输入后自动恢复。
- **会议抑制**：当前台应用命中的规则带 `suppressIdle: true`（腾讯会议 / 飞书 / 钉钉 / 企微 / Zoom / Teams / Slack）时，**不触发空闲挂起**——因为开会时确实极少碰键鼠，否则必然误判。
  - 设置项 `idle.suppressForMeetingApps`，默认开，可关。
  - ⚠️ 副作用：挂着会议软件干别的也不会被空闲挂起。这是有意为之的权衡（§14-Q3 有说明）。
- 锁屏 / 睡眠通过 `SessionSwitch` / `PowerModeChanged` 直接挂起。

#### 4.5.6 跨类别阈值策略（用户可选）

设置项 `timing.crossCategoryThresholdMode`：

| 取值 | 含义 | 例：run 内出现游戏(5) + 视频(10) |
|---|---|---|
| **`min`（默认）** | 取运行期内出现过类别的**最小**阈值 | 5 分钟 |
| `avg` | 取**均值** | 7.5 分钟 |
| `max` | 取**最大**阈值 | 10 分钟 |
| `sum` | 各类别阈值**累加** | 15 分钟 |
| `current` | 实时取**当前所在类别**的阈值 | 切到视频时为 10 分钟 |

> 默认 `min`：只要这段连续娱乐里碰过游戏，整段就按最严格的 5 分钟算——最贴合"这段时间就是没在干活"的直觉。

**示例时间线**（策略 `min`，阈值：游戏 5 / 视频 10 / 聊天 10）

| 时刻 | 前台 | run 状态 | 结果 |
|---|---|---|---|
| 10:00 | VS Code | 无 run | 计时中 |
| 10:10 | 游戏 | run 开始，阈值 = 5 | 待判定 |
| 10:13 | B 站视频 | run 继续（阈值仍 5） | 待判定 |
| **10:15** | 视频 | 达 5 分钟 ≥ 5 → 挂起 | **挂起**，10:10–10:15 作废 |
| 10:33 | Word | run 结束 | 恢复计时 |

### 4.8 窗口段整合与站点识别（本次新增核心）

#### 4.8.1 窗口段整合

**不逐条记录采样**。`SegmentBuilder` 把连续相同的（进程 + 展示名 + 类别 + 是否计入）采样**合并成一个窗口段**：

```
窗口段 = { startedAt, endedAt, seconds, appName, sitePlatform, category, counted, runId }
```

- 2 秒采样下，一次"写代码 47 分钟"= **1 条记录**，而不是 1410 条。
- 段在以下时刻闭合：窗口切换（经防抖确认）、分类变化、状态变化（挂起/恢复）、会话停止。
- 末尾加 `minSegmentSeconds` 过滤：短于 5 秒的碎片不入库（并入相邻段）。

效果：一天几十条记录，明细表可读，归档压力小。

## 6. 数据模型（SQLite）

```sql
-- 项目（软删除）
CREATE TABLE projects (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  name         TEXT    NOT NULL,
  color        TEXT,
  is_archived  INTEGER NOT NULL DEFAULT 0,
  deleted_at   TEXT,                       -- NULL = 正常；非空 = 在回收站
  sort_order   INTEGER NOT NULL DEFAULT 0,
  created_at   TEXT    NOT NULL
);
CREATE UNIQUE INDEX ux_projects_active_name ON projects(name) WHERE deleted_at IS NULL;

-- 计时会话
CREATE TABLE sessions (
  id                  INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id          INTEGER NOT NULL REFERENCES projects(id),
  started_at          TEXT    NOT NULL,           -- 归属日以此为准
  ended_at            TEXT,                       -- NULL = 未结束
  state               TEXT    NOT NULL,           -- active | paused | ended
  stop_reason         TEXT,                       -- USER_STOP|USER_EXIT|AUTO_END|CRASH
  net_seconds         INTEGER NOT NULL DEFAULT 0,
  suspended_seconds   INTEGER NOT NULL DEFAULT 0,
  user_paused_seconds INTEGER NOT NULL DEFAULT 0,
  idle_seconds        INTEGER NOT NULL DEFAULT 0,
  note                TEXT,
  last_heartbeat_at   TEXT                        -- 每 30s 更新
);
CREATE INDEX idx_sessions_started ON sessions(started_at);
CREATE INDEX idx_sessions_state   ON sessions(state);

-- 状态事件流
CREATE TABLE events (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id    INTEGER REFERENCES sessions(id),
  at            TEXT    NOT NULL,
  type          TEXT    NOT NULL,  -- START|STOP|PAUSE|UNPAUSE|SUSPEND|RESUME|IDLE|IDLE_END
                                   -- |AUTO_END|EXIT_SAVE|RESUME_FROM_EXIT|SWITCH_PROJECT
                                   -- |RULE_HIT|RUN_DISCARDED|RECALC
  category      TEXT,
  process_name  TEXT,
  site_platform TEXT,
  window_title  TEXT,              -- 仅当隐私设置允许时写入
  window_class  TEXT,
  reason        TEXT
);
CREATE INDEX idx_events_at      ON events(at);
CREATE INDEX idx_events_session ON events(session_id);

-- 窗口段（整合后的明细，统计与复盘主力）
CREATE TABLE activity_segments (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id    INTEGER NOT NULL REFERENCES sessions(id),
  project_id    INTEGER,
  started_at    TEXT    NOT NULL,
  ended_at      TEXT    NOT NULL,
  seconds       INTEGER NOT NULL,
  category      TEXT    NOT NULL,
  counted       INTEGER NOT NULL,   -- 1=计入有效工时 0=作废
  run_id        INTEGER,            -- 所属娱乐连续运行
  app_name      TEXT    NOT NULL,   -- 友好应用名，如 "Visual Studio Code"
  site_platform TEXT,               -- 浏览器站点平台名，如 "哔哩哔哩"
  title_detail  TEXT,               -- 完整标题，仅隐私设置允许时写入
  process_name  TEXT
);
CREATE INDEX idx_seg_started ON activity_segments(started_at);
CREATE INDEX idx_seg_session ON activity_segments(session_id);
CREATE INDEX idx_seg_project ON activity_segments(project_id, started_at);

-- 娱乐连续运行（便于复盘"整段摸鱼"）
CREATE TABLE entertainment_runs (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id    INTEGER NOT NULL REFERENCES sessions(id),
  started_at    TEXT    NOT NULL,
  ended_at      TEXT,
  seconds       INTEGER NOT NULL DEFAULT 0,
  threshold_used INTEGER,
  discarded     INTEGER NOT NULL DEFAULT 0,  -- 1 = 超阈值作废
  categories    TEXT                         -- 逗号分隔，如 "game,video"
);

-- 日汇总（归档产物）
CREATE TABLE daily_rollup (
  day               TEXT NOT NULL,
  project_id        INTEGER NOT NULL,
  net_seconds       INTEGER NOT NULL,
  suspended_seconds INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (day, project_id)
);

CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE schema_version (version INTEGER NOT NULL);
```

### 统计口径（严格遵守）

1. 会话**不切割时间**，跨零点仍是同一条。
2. **归属日 = `sessions.started_at` 的日期**。22:00 开始、次日 02:00 结束的 4 小时，**全部计入 22:00 那天**。
3. **总工时统计一律从 `sessions` 聚合**（已结束的按实际值，`state='paused'` 的按当前累计值），不用 `activity_segments` 切分，避免两套口径打架。
4. `activity_segments` 只用于**窗口占用明细展示**与**历史回算**。
5. `daily_rollup` 归档时也按 `sessions.started_at` 的日期写入，口径一致。

> UI 上标注小字："跨天会话计入开始当天"。

### 其他

- **计时精度**：有效时长用 `Stopwatch` 单调时钟累积；改系统时间不影响时长。
- **写库节流**：`activity_segments` 仅在窗口段闭合时写一次；心跳每 30 秒。
- **完整性自检**：启动 `PRAGMA quick_check`。

## 9. 关键实现要点

1. **P/Invoke 清单**：`GetForegroundWindow`、`GetWindowThreadProcessId`、`GetWindowTextW`、`SendMessageTimeout`、`GetClassNameW`、`GetWindowRect`、`EnumChildWindows`、`GetLastInputInfo`、`MonitorFromWindow`、`GetMonitorInfo`、`QueryFullProcessImageName`。
2. **单调时钟**：`Stopwatch` 累计有效时长。
3. **数据目录可写性探测**：启动写临时文件测试；失败回退 `%APPDATA%` 并提示。
4. **单实例**：命名 `Mutex`；二次启动 `FindWindow` + `SetForegroundWindow` 唤醒。
5. **退出保存并恢复（FR-22）**：
   - `FormClosing` / 托盘"退出" → 结束当前窗口段 → `session.state = 'paused'`、`stop_reason = 'USER_EXIT'`、`ended_at` 留空、写 `EXIT_SAVE` 事件 → 落库后退出。
   - 下次启动检测到 `state='paused' AND stop_reason='USER_EXIT'` 的会话 → 自动恢复为 `PausedByUser` 状态，主界面顶部提示「已恢复上次会话（已暂停 8 小时）　[继续] [结束并保存]」。
   - 用户点「继续」→ `state='active'`，写 `RESUME_FROM_EXIT` 事件，计时接着累加。
6. **历史回算（FR-18）**：
   - 触发点：判定纠错时选择"回算历史并修正统计"。
   - 对话框：选择范围（最近 7 天 / 最近 30 天 / 全部未归档明细）+ **预览**（"将影响 128 条窗口段，今日工时 +1h20m，昨日 -0h40m"）+ 确认。
   - 算法：对范围内 `activity_segments` 用新规则重判 `category` → 重算 `counted` → 按 session 重算 `net_seconds` / `suspended_seconds` → 写 `RECALC` 事件留痕。
   - 约束：回算范围**不超过未归档明细的边界**（已归档进 `daily_rollup` 的部分不参与，提示用户）。回算可撤销（保留最近一次回算前的快照）。
7. **自动结束会话（FR-24）**：会话内 `idle_seconds + suspended_seconds` 累计 ≥ 60 分钟 → 结束会话、`stop_reason='AUTO_END'`、写 `AUTO_END` 事件、托盘气泡提示一次。
8. **归档任务（FR-25）**：启动时 + 每日一次，把 30 天前的 `activity_segments` 聚合进 `daily_rollup`（按 session 归属日）后删除明细；同时清理回收站中超 30 天的项目（需设置页开关确认）。
9. **SQLite**：`journal_mode=WAL`、`synchronous=NORMAL`；批量写单事务。
10. **高 DPI**：`app.manifest` 声明 `PerMonitorV2`；悬浮窗需正确适配缩放。
11. **锁屏与电源**：`SystemEvents.SessionSwitch`、`PowerModeChanged` → 挂起 / 恢复。
12. **提权进程降级**：路径取不到时只用进程名匹配。
13. **日志**：`logs\app-yyyyMMdd.log` 滚动。
14. **性能预算**：常驻内存 < 90 MB（含悬浮窗），CPU 平均 < 0.5%。

| 21 | 会议窗口前台 + 后台小窗放视频 | 按前台判定为工作（§14-Q3 说明与选项） |
| 22 | 任务栏点击切换应用 | 前台短暂为 `Shell_TrayWnd` → `Inherit`，防抖兜底 |
| 23 | 删除项目后又想看数据 | 回收站保留 30 天，可找回 |
| 24 | 悬浮窗拖到屏幕外 | 启动时校验位置，越界则回到默认位置 |

## 11. 固有局限（提前知道，不是 Bug）

1. **只看焦点，不看行为**：前台是什么就判什么，后台跑什么不管。双屏并行时以焦点所在窗口为准。
2. **虚拟机 / 远程桌面内部不可见**：全屏 VMware / VirtualBox / 向日葵 / ToDesk 等，前台一律是那个远程工具进程，里面在写代码还是打游戏无法区分（`mstsc` 默认归 `Work`）。
3. **会议窗口前台 + 后台播放视频无法区分**：前台是会议窗口就判工作（且不因空闲挂起）；如果视频小窗在前台，则判娱乐。这是"只看焦点"的必然结果，设置中留有调整项。
4. **浏览器标签粒度**：只能看活动标签标题。同窗口另一标签在放视频不影响判定（符合预期）。
5. **站点识别依赖标题特征**：极少数站点标题不含可识别关键词会落到"网页浏览"兜底，可在 `sites.json` 补充。
6. **游戏进程名无法穷举**：内置常见平台 + 游戏；冷门游戏需手动加规则，或用"独占全屏 → 疑似游戏"后备开关。
7. **触摸屏输入**：依赖系统空闲计时器刷新，绝大多数设备可用；若实测异常，需补 RawInput 方案（暂缓）。
8. **单文件 exe 可能被杀软误报**：.NET 单文件发布的常见现象，需要时加白名单。
