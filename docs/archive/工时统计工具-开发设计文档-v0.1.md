## 1. 项目目标

做一个 Windows 桌面常驻工具，帮助用户**准确记录真实工作时长**：

- 由用户**手动**开始 / 停止计时（不自动开始，不替用户判断"你该上班了"）。
- 计时期间**持续监测当前前台被激活的窗口**，据此判定用户是否在真正工作。
- 前台是游戏 / 视频 / 聊天类软件、且**连续停留超过设定阈值**时，自动**暂停**计时。
- 前台切回工作软件或系统组件（如文件资源管理器）后，自动**恢复**计时。
- **只关注前台窗口**，因此后台挂着游戏、聊天软件不影响计时正确性。
- 提供 GUI、统计、分项目计时、任务栏托盘图标、右键菜单、设置与配置文件。

### 非目标（本期不做）

- ❌ 跨设备 / 云端同步工时数据
- ❌ 团队管理、上报、审批流
- ❌ 键盘记录、屏幕截图、内容审查等侵犯隐私的能力
- ❌ 移动端 / Web 端

## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 / 框架 | **C# + .NET 8 (net8.0-windows) + WinForms** | 用户指定；窗口监测与托盘是 Windows 原生能力，WinForms 的 `NotifyIcon` 即原生托盘，P/Invoke 无额外依赖 |
| 目标框架 | `net8.0-windows`（LTS） | 本机已装 WindowsDesktop 运行时 8.0.28。若 NuGet 还原 8.0 目标包受阻，可切换为 `net10.0-windows`（本机已装 10.0.9） |
| 前台窗口监测 | P/Invoke → `user32.dll` / `kernel32.dll` | 无需第三方库，500ms 一次采样，CPU 占用可忽略 |
| 数据存储 | **SQLite**（`Microsoft.Data.Sqlite`） | 单文件、免安装、支持按项目/日期聚合查询与索引 |
| 配置 | `config.json`（`System.Text.Json`），程序内设置界面与文件**双向同步** | 用户可手改配置文件，也可用 GUI 改 |
| 图表 | 自绘 GDI+ 轻量图表（柱状/占比条） | 避免引入重型图表库，保持单个 exe 体积小 |
| 打包 | `dotnet publish -p:PublishSingleFile=true --self-contained` | 产出单个 exe，目标机器无需装 .NET |
| 单元测试 | xUnit（`WorkTimer.Core` 与 UI 解耦） | 判定引擎与阈值状态机是本项目的风险核心，必须可测 |

│                                                                          │
│  Monitoring/  ForegroundWindowWatcher ──► WindowInfo(采样结果)            │
│               IdleDetector（AFK 空闲检测，GetLastInputInfo）              │
│  Classification/  RuleEngine ──► ClassificationResult(Category, 命中规则) │
│  Timing/      TimerEngine（状态机 + ThresholdTracker + SegmentBuilder）   │
│  Data/        SqliteRepository / Migrations / Models                     │
│  Config/      AppConfig / ConfigStore / RuleStore                        │
│  Stats/       StatsService（按项目、按天/周/月聚合）                       │
└──────────────────────────────────────────────────────────────────────────┘
                                │
                        %APPDATA%\WorkTimer\

**分层原则**：`Core` 不引用任何 UI 类型，`Monitoring` 采样结果以纯数据（`WindowInfo`）向 `Timing` 传递。这样判定引擎、阈值状态机、统计聚合都能在单元测试里用伪造窗口序列驱动，不依赖真实桌面。

## 4. 核心：判定引擎

这是整个工具最关键的模块，请重点评审。

### 4.1 采样

每 **500ms**（可配 `pollIntervalMs`）采集一次前台窗口：

| 字段 | 来源 |
|---|---|
| `Hwnd` | `GetForegroundWindow()` |
| `Pid` | `GetWindowThreadProcessId()` |
| `ProcessName` | 由 Pid 取进程名（`QueryFullProcessImageName`，失败降级为 `Process.ProcessName`） |
| `ProcessPath` | 同上，提权进程可能取不到 → 留空 |
| `WindowTitle` | `GetWindowTextW`（长度 0 时降级 `SendMessageTimeout(WM_GETTEXT)`） |
| `WindowClass` | `GetClassNameW` |
| `IsFullscreen` | 窗口矩形 == 显示器矩形且无边框（辅助判定独占全屏游戏） |
| `IdleSeconds` | `GetLastInputInfo()` |

**UWP 特例**：UWP 应用（含部分系统设置、商店应用、Xbox 应用）的前台窗口属于 `ApplicationFrameHost.exe`，真实进程藏在子窗口里。处理方式：若进程名为 `ApplicationFrameHost`，用 `EnumChildWindows` 找 `Windows.UI.Core.CoreWindow` 类子窗口并取其 PID。

**防抖（重要）**：仅当新窗口**连续占据前台 ≥ 3 秒**（可配 `minSegmentSeconds`），才认定为"窗口切换"并送入判定。这样微信新消息弹窗、通知横幅、输入法候选、Alt+Tab 途中的瞬间窗口都不会打断计时。

### 4.2 窗口分类

| 分类值 | 含义 | 默认阈值 |
|---|---|---|
| `Work` | 工作软件、系统组件 | — |
| `Game` | 游戏 | 0 分钟（立即暂停） |
| `Video` | 视频播放器 | 0 分钟（立即暂停） |
| `Chat` | 聊天 / 社交工具 | **10 分钟** |
| `Neutral` | 无法判定 | 按 `browserFallback` 策略，默认 **计入工作** |
| `Self` | 本工具自己的窗口 | 继承上一个有效分类，不打断计时 |

> 阈值**按类别可配置**（用户选择项）：游戏 / 视频 / 聊天各自独立设阈值，`0 = 立即暂停`。此外单条规则可用 `thresholdMinutes` 覆盖所属类别的默认值。

### 4.3 规则匹配

匹配顺序 **first-match-wins**（先命中先用）：

1. **用户自定义规则**（`rules.user.json`，设置界面里可拖动排序、改优先级）
2. **内置规则库**（`rules.builtin.json`，随程序升级覆盖）
3. **兜底策略**：`Neutral` → 按配置计入工作

单条规则结构：

```
{
  "id": "u-1", "enabled": true, "order": 10, "category": "work",
  "processPattern": "devenv*",      // 支持 * 通配，匹配进程名（不含 .exe）
  "titlePattern": null,             // 标题关键词
  "titleIsRegex": false,            // true 时 titlePattern 按正则解析
  "classPattern": null,             // 窗口类名
  "matchMode": "process",           // process | title | class | all | any
  "thresholdMinutes": null,         // 覆盖类别默认阈值
  "note": "Visual Studio"
}
```

**内置规则库（初始内容，覆盖常见场景）**

- `Work`：`devenv`、`Code`、`rider64`、`idea64`、`pycharm64`、`sublime_text`、`WindowsTerminal`、`powershell`、`cmd`、`conhost`、`explorer`（文件资源管理器）、`mstsc`（远程桌面）、`WINWORD`、`EXCEL`、`POWERPNT`、`wps`、`et`、`wpp`、`notepad`、`Notepad++`、`Everything`、`SnippingTool`，以及 `Progman`/`WorkerW`（桌面）、`Shell_TrayWnd`（任务栏）、`ShellExperienceHost`（开始菜单）等系统组件。
- `Game`：`steam`、`steamwebhelper`、`wegame`、`EpicGamesLauncher`、`Battle.net`、`GalaxyClient`、`LeagueClient`、`dota2`、`cs2`、`GenshinImpact`、`YuanShen`、`StarRail`，并额外提供"**独占全屏 + 未命中任何其他规则 → 疑似游戏**"的后备信号（默认关闭，可在设置中开启）。
- `Video`：`PotPlayerMini64`、`vlc`、`mpv`、`mpc-hc64`、`bilibili`（客户端）、`QQLive`、`iqiyi`、`YoukuClient`、`douyin`、`TikTok`。
- `Chat`：`WeChat`、`Weixin`、`QQ`、`TIM`、`DingTalk`、`WXWork`、`Feishu`、`Lark`、`Telegram`、`Discord`、`Slack`、`Zoom`、`TencentMeeting`、`wemeetapp`。

> 说明：企业微信 / 钉钉 / 飞书 / 腾讯会议既可能是工作沟通也可能是闲聊，统一归入 `Chat` 走 10 分钟阈值——只算"长时间停在里面"的场景，短沟通不误杀。如不认同请在评审时提出。

**浏览器专项**（用户选择项：标题关键词判定）

命中 `browser.processes`（`chrome`、`msedge`、`firefox`、`brave`、`360se`、`QQBrowser`、`opera` 等）后，用窗口标题关键词二次判定：

- `browser.entertainmentTitleKeywords`：bilibili、哔哩哔哩、youtube、netflix、爱奇艺、腾讯视频、优酷、芒果TV、抖音、douyin、西瓜视频、斗鱼、虎牙、twitch、微博、weibo、知乎、小红书、贴吧、豆瓣、虎扑、reddit、tiktok、直播 …
- `browser.workTitleKeywords`：github、gitlab、stackoverflow、stack overflow、developer.mozilla、learn.microsoft、docs.、api.、confluence、jira、notion、公司内网域名（用户可加）…
- 两者都未命中 → 按 `browserFallback`（默认 `work`）。
- **匹配优先级可切换**：默认"工作关键词优先"（避免误杀查资料），可切为"娱乐关键词优先"（工时更保守）。

### 4.4 阈值状态机

状态定义：

| 状态 | 含义 | 是否计时 |
|---|---|---|
| `Stopped` | 用户未开始 | ❌ |
| `Working` | 正常计时 | ✅ |
| `SuspendedAuto` | 娱乐前台连续超阈值 → 自动挂起 | ❌ |
| `PausedByUser` | 用户手动暂停 | ❌ |
| `IdleAway` | AFK 无输入超阈值（可关） | ❌（可配为"照常计时"） |

每个娱乐类别维护一个**连续停留计时器** `continuousMs[category]`：

```
每 500ms 采样一次 → 得到 category

若 状态 == PausedByUser:  忽略前台变化，直到用户点"继续"

若 category == Self:      不改变任何计时器（打开自己的窗口不打断）

若 category ∈ {Game, Video, Chat}:
    continuousMs[其它娱乐类别] = 0
    continuousMs[category] += 500ms
    若 continuousMs[category] >= threshold[category]:
        Working/IdleAway → SuspendedAuto   （写 SUSPEND 事件）
        （已经是 SuspendedAuto 则保持不变）

若 category ∈ {Work, Neutral}:
    所有 continuousMs[*] = 0
    若 状态 == SuspendedAuto: SuspendedAuto → Working（写 RESUME 事件）
```

**关键设计点 —— 是否追溯扣除？**

"连续使用超过 10 分钟才暂停"采用**字面语义**：前 10 分钟仍计入工时，第 10 分钟起才停止计时。理由：这是"允许短暂切出去看一眼"的宽容设计。

> ⚠️ 已知规避风险：若每 9 分钟切回工作窗口一次，永远触发不了阈值。为此提供可选**严格模式** `timing.retroactiveDeduct = true`：判定为摸鱼后，把该段娱乐停留时长也追溯扣除。另可选**滚动窗口统计**（如"最近 30 分钟内娱乐前台累计 ≥ 15 分钟即挂起"）作为进阶方案。默认关闭，避免误伤。

**挂起后的恢复**：一旦切回 `Work`/`Neutral` 窗口，**立即**恢复计时（不再等阈值），并写 `RESUME` 事件。

**AFK 处理**：`IdleSeconds` 超过 `idleThresholdMinutes`（默认 10）→ 转 `IdleAway`；有输入后自动恢复。锁屏 / 睡眠通过 `SystemEvents.SessionSwitch` / `PowerModeChanged` 直接挂起。

### 4.5 "后台挂着不影响"的实现说明

引擎**只读取前台窗口**，不枚举后台进程列表，因此：后台挂着游戏 / 微信 / 播放器，前台在写代码 → 分类恒为 `Work` → 正常计时，完全不受影响。这是架构层面的保证，而非规则配置。

### 4.6 判定可验证性（强烈建议保留的功能）

误判是这类工具的最大痛点。主窗口实时显示：

> 当前前台：`chrome.exe` — `B站 首页 - Google Chrome`
> 判定结果：**娱乐 · 视频**（命中内置规则：标题含"bilibili"） → 2 分 13 秒后挂起

旁边提供两个按钮：**「改为工作」** / **「改为娱乐」**，点击即写入一条用户规则并**立即重算本次判定**。用户不需要去翻配置文件猜格式。

## 6. 数据模型（SQLite）

```sql
-- 项目
CREATE TABLE projects (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  name         TEXT    NOT NULL UNIQUE,
  color        TEXT,                            -- 图表配色 #RRGGBB
  is_archived  INTEGER NOT NULL DEFAULT 0,
  sort_order   INTEGER NOT NULL DEFAULT 0,
  created_at   TEXT    NOT NULL
);

-- 计时会话：一次"开始 → 停止"为一条；跨零点不切割，按天统计交给 activity_segments
CREATE TABLE sessions (
  id                  INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id          INTEGER NOT NULL REFERENCES projects(id),
  started_at          TEXT    NOT NULL,          -- ISO8601 带时区偏移
  ended_at            TEXT,                      -- NULL = 进行中（崩溃恢复依据）
  net_seconds         INTEGER NOT NULL DEFAULT 0,-- 有效计时（不含挂起/暂停）
  suspended_seconds   INTEGER NOT NULL DEFAULT 0,
  user_paused_seconds INTEGER NOT NULL DEFAULT 0,
  idle_seconds        INTEGER NOT NULL DEFAULT 0,
  note                TEXT,
  last_heartbeat_at   TEXT                       -- 每 30s 更新，崩溃时用于补记
);

-- 状态事件流（可用于完整复盘）
CREATE TABLE events (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id    INTEGER REFERENCES sessions(id),
  at            TEXT    NOT NULL,
  type          TEXT    NOT NULL, -- START|STOP|SUSPEND|RESUME|PAUSE|UNPAUSE|SWITCH_PROJECT|IDLE|IDLE_END|RULE_HIT
  category      TEXT,             -- Work|Game|Video|Chat|Neutral|Self
  process_name  TEXT,
  process_path  TEXT,
  window_title  TEXT,
  window_class  TEXT,
  reason        TEXT              -- 命中的规则 id / 阈值说明
);
CREATE INDEX idx_events_at      ON events(at);
CREATE INDEX idx_events_session ON events(session_id);

-- 前台窗口占用明细（按"窗口段"聚合，统计与事后复盘的主力表）
CREATE TABLE activity_segments (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id   INTEGER NOT NULL REFERENCES sessions(id),
  project_id   INTEGER,
  started_at   TEXT    NOT NULL,
  ended_at     TEXT    NOT NULL,
  seconds      INTEGER NOT NULL,
  category     TEXT    NOT NULL,
  counted      INTEGER NOT NULL,   -- 1=计入工时 0=未计入
  process_name TEXT,
  window_title TEXT,
  window_class TEXT
);
CREATE INDEX idx_seg_started ON activity_segments(started_at);
CREATE INDEX idx_seg_project ON activity_segments(project_id, started_at);

-- 键值配置（阈值等以便查询；权威来源仍是 config.json，两者启动时同步）
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);

-- 迁移版本
CREATE TABLE schema_version (version INTEGER NOT NULL);
```

**设计说明**

- **不切割跨天会话**：跨零点时 `sessions` 仍是同一条，"今天干了多久"由 `activity_segments` 按日期聚合得出，比切割会话更灵活，也不会因为切割产生半截会话。
- **计时精度**：有效时长以 `Stopwatch`（单调时钟）累积，写入 `net_seconds`；即使系统时间被修改也不影响时长正确性。`started_at` 等墙钟时间仅用于展示与聚合。
- **写库节流**：`activity_segments` 仅在窗口段结束（切换/暂停/停止）时写一次；`sessions.last_heartbeat_at` 每 30 秒更新一次。避免 500ms 一次的高频磁盘 IO。
- **崩溃恢复**：启动时查 `ended_at IS NULL` 的会话 → 弹窗提示"上次会话未正常结束，是否补记到 `last_heartbeat_at`？"（补记 / 丢弃 / 手动指定截止时间）。

## 9. 关键实现要点

1. **P/Invoke 清单**（`user32` / `kernel32`）：`GetForegroundWindow`、`GetWindowThreadProcessId`、`GetWindowTextW`、`SendMessageTimeout`、`GetClassNameW`、`GetWindowRect`、`EnumChildWindows`、`GetLastInputInfo`、`MonitorFromWindow`、`GetMonitorInfo`、`QueryFullProcessImageName`。
2. **单调时钟**：计时用 `Stopwatch`，不用 `DateTime.Now` 差值。
3. **单实例**：命名 `Mutex`；二次启动时用 `FindWindow` + `SetForegroundWindow` 唤醒已有主窗口后退出。
4. **高 DPI**：`app.manifest` 声明 `PerMonitorV2`，否则多显示器缩放下界面模糊。
5. **提权进程降级**：读取系统级 / 管理员进程的完整路径可能失败，此时只用进程名匹配（规则已按进程名设计，不受影响）。
6. **锁屏与电源**：`Microsoft.Win32.SystemEvents.SessionSwitch`（锁屏/解锁）、`PowerModeChanged`（睡眠/唤醒）→ 挂起 / 恢复。
7. **自身窗口特例**：`Self` 分类只针对本进程的窗口；打开统计窗口不会中断计时。
8. **写库节流与事务**：批量写 `activity_segments`，单事务提交；DB 开启 WAL 提升并发健壮性。
9. **日志**：`logs\app-yyyyMMdd.log` 滚动，记录采样异常、DB 错误、状态变迁（默认 Info 级）。
10. **性能预算**：常驻内存 < 80MB，CPU 平均 < 1%（500ms 采样足够轻量）。

## 10. 边缘场景与处理

| # | 场景 | 处理 |
|---|---|---|
| 1 | 全屏独占游戏 | `GetForegroundWindow` 仍可取到；配合 `IsFullscreen` 与游戏规则/后备信号 |
| 2 | UWP 应用（进程显示为 `ApplicationFrameHost`） | 枚举子窗口取真实 PID |
| 3 | 微信/通知弹窗抢占前台 1~2 秒 | 防抖：< 3 秒的窗口切换不改变判定 |
| 4 | 多显示器 / 虚拟桌面切换 | 以前台窗口为准，不区分显示器 |
| 5 | 锁屏 / 睡眠 / 休眠 / 远程桌面断连 | 事件驱动挂起，恢复后按当前前台重新判定 |
| 6 | 用户修改系统时间 / 时区 | 时长用单调时钟，不受影响；跨时区仅影响展示 |
| 7 | 提权进程（任务管理器、管理员 IDE） | 路径读取降级为进程名 |
| 8 | 浏览器全屏看视频 | 标题仍是浏览器标题，走关键词判定 |
| 9 | 应用正被启动、窗口尚未就绪 | 防抖窗口 + 命中不到规则时回退上一个稳定分类 |
| 10 | 数据库被云盘同步锁定 | 重试 + 友好提示，切换 WAL；启动时自检 DB 完整性 |
| 11 | 长时间不关机、跨多天 | 会话不切割，按 `activity_segments` 日期聚合 |
| 12 | 手动暂停期间切了很多窗口 | `PausedByUser` 状态优先，忽略前台变化 |
| 13 | 用户开始计时后立刻打开游戏 | 按阈值处理；游戏阈值 0 → 立即挂起，符合预期 |

7. **数据目录**：`%APPDATA%\WorkTimer\`（默认）还是你想放到指定目录（如 `D:\WorkTimerData\`）？
